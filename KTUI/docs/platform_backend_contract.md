# KTUI 平台后端契约

新平台实现 `IPlatformBackend` 和 `IPlatformWindow`，并提供调度、帧时钟、字体解析三个服务。平台没有对应系统功能时，也要在自己的实现里明确提供替代行为，例如无窗口后端用内存剪贴板和离屏像素缓冲。全帧 RGBA 呈现复用必需的区域呈现接口。

| 接口 | 必须实现的职责 |
| --- | --- |
| `IPlatformBackend` | 初始化、关闭、创建窗口、事件分发、事件轮询与等待、剪贴板读写和三个服务的访问入口 |
| `IPlatformWindow` | 尺寸、位置、可见性、焦点、全屏和所有窗口状态，窗口外观和标题栏，DPI、绘制比例、刷新率，原生窗口和显示句柄，RGBA 呈现、重绘请求，IME 启停、候选框定位、指针形状、生命周期回调 |
| `IPlatformDispatcher` | 跨线程投递任务、在 UI 线程执行、查询待办任务 |
| `IVSyncSource` | 请求和取消下一帧回调、查询休眠状态 |
| `IFontResolver` | 按通用分类与字重解析字体、按字体名称解析回退 |

## 输入事件

- 所有事件在 UI 线程按顺序发送，并携带所属窗口句柄。指针位置和候选框位置使用窗口客户区坐标。绘制比例只用于从客户区坐标换算到渲染像素。
- `KeyDown` / `KeyUp` 用于按键、导航、快捷键。当前键码是 KTUI 统一采用的 Windows 虚拟键值。按键事件的 `text` 留空。交给系统 IME 消费的组合键无需再次送给控件。
- `ImeComposition` 用于暂存预编辑文字。空字符串清除预编辑，`ime_cursor_byte` 是 UTF-8 字节偏移。系统未提供位置时使用字符串末尾。
- `ImeCommit` 用于最终文字，普通键入、输入法确认和平台文本粘贴各提交一次。输入法取消或失焦清理组合状态。每个平台为粘贴选定一个来源，避免快捷键与系统粘贴同时插入。
- Web 使用聚焦的 DOM 输入框接收普通输入及组合事件。Windows 使用 IMM32 和 `WM_CHAR`。X11 使用 XIM，具体输入法可自行显示预编辑界面并向应用返回确认文本。无窗口后端由调用方注入同样的事件以供测试。

接入验收应覆盖普通键入、退格和快捷键、组合更新后确认一次、取消、焦点切换、剪贴板、候选框定位以及窗口重绘。
